Part A.4: Blend the Images into a Mosaic

In the previous section, the conclusion was that bilinear was the better option due to its trade-off between speed and quality, so the focus will be on using the bilinear interpolation method.

Process:

  • Take two images of the same scene with decent overlap, with enough shared keypoints between the two.
  • Select six key points that are shared between images. When selecting the key points there is a focus on selecting defined features in an intuitive order as this helps with accuracy and consistency. If the key points are selected in the wrong order, mosaics will look incorrect. If dull features are selected, it could lead to a mosaic that does not line up properly due to error between the points in the two images. This step is about calculating the homography matrix.
  • When warping the image, the final mosaic canvas needs to be calculated. This is done by going through each image and its related H matrix in order to get the warped corners. Once all warped corners are calculated, it is easy to get the maximum and minimum x and y values to get the shape of the final mosaic. Along with this step is the calculation of the translation matrix which moves the bounding box of the mosaic to be lined up with the top left corner.
  • Now that the final mosaic canvas is calculated, each image needs to be placed onto the canvas. In order to do this, the images need to be warped using the methods discussed in the previous question and a matching weight map needs to be calculated. The weight map spans the mosaic and uses a distance transform to make the center of the image 1 while falling smoothly toward 0 at the edges. The mask is warped like the image so it lines up with the warped pixels.
  • Now that the image is warped correctly, and the weight mask is calculated, the next step is to blend the images correctly using these values to create the mosaic. Two blending techniques were used as part of a one-shot procedure: feather blending and Laplacian pyramid blending.
  • Feather Blending: Each output pixel is a weighted average of the overlapping images. The highest weight is one in the middle and fades to zero at the edges of the image, causing one image to take over the other gradually instead of abruptly switching between the two. This method tends to hide the seams between images better but averages fine details, which can show up as blur or ghosting.
  • Laplacian Pyramid Blending: Each image is split into a low-frequency part and a detail part, which creates a Laplacian pyramid with a single level. This should improve on the blending process because different frequencies need different treatment. Each frequency is blended its own way and the results are added back together. Low frequencies should blend over a wider area so there is no visible seam, while high frequencies should blend over a narrow area. This is where Laplacian pyramid blending gets its advantages.

Comparing the two blending techniques, some ghosting and blur shows up when using feather blending. The Laplacian blending technique seems to improve these shortcomings, but the seam between the two images is more noticeable. Personally, the Laplacian blending technique creates a more realistic image, as it removes the ghosting at the cost of a more noticeable seam.

Part B: Feature Matching for Autostitching

Part B.1: Harris Corners and ANMS

From the output images, it is clear that ANMS is a vital part of corner detection. The Harris corner detector is able to find a lot of corners, so many that they are not valuable until most of them are removed using a technique such as ANMS. The corner detection is the first step in the auto mosaic pipeline.

ANMS keeps the 500 corners with the largest suppression radius, where a corner’s radius is the distance to the nearest corner that is significantly stronger than it (using a robustness constant of c = 0.9). This keeps strong corners while spreading them evenly across the image.

Part B.2: Feature Descriptors

The images show some of the interest points which the Harris algorithm detects and how they are saved as feature descriptors. These descriptors will be used to find the same points in the other image. If an area in the other image resembles one of these descriptors, then it will think it is the same interest point; this will lead to feature matching in the next section.

Each descriptor is created by blurring the image with a Gaussian (σ = 2), taking the 40x40 window around each corner and downsampling it to an 8x8 patch. Each patch is then bias/gain normalized by subtracting its mean and dividing by its standard deviation, which makes the descriptors less sensitive to changes in brightness and contrast.

Part B.3: Feature Matching

Overall, the feature matching does a pretty good job matching corresponding features between the two images; however, there are a few features that get matched that are wrong for each image. This is fine because RANSAC should filter out the bad matches during its homography computation process.

For each descriptor, the two nearest neighbours in the other image are found. Following Lowe’s approach, a match is only kept if the ratio between the first and second nearest neighbour (squared) distances is below 0.5. This removes ambiguous matches, where a feature looks similar to more than one point in the other image.

Part B.4: RANSAC and Automatic Mosaics

RANSAC was run for 2000 iterations. In each iteration, four random matches are chosen and used to compute a homography, which is then applied to all of the matched points. A match counts as an inlier if its projected point lands within 2 pixels of its matching point. The homography with the most inliers is kept, and the final homography is recomputed using least squares on all of its inliers.

Manual vs Automatic

Each comparison shows the manual mosaic from Part A next to the automatic mosaic, both using bilinear interpolation and Laplacian blending.

RANSAC improved the feature matching drastically by removing the invalid matched features. Overall, the automatic mosaic creates better results as it removes human error from the key point selection. This is most visible in the meeting room mosaic, where the manual version shows a slight seam through the TV, while the automatic version lines up cleanly. The homography is also estimated from many verified inliers (13–20 per pair) rather than a few hand-clicked points, so small errors in any single point have much less effect on the final alignment.
